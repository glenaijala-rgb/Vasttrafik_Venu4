# Version 2.2 – Åk hem

## Funktion och status
Första implementationen av backend och Garmin-källkod. Inte driftklar förrän APR-svar och hållplatsregler har verifierats live, SDK-build är grön och den verkliga klockan är testad. Ingen demo-trafik i produktion. Hem är förvalt; Hållplats växlar Hem/Jobb; Åk hem öppnar tredje sidan. Glance A är oförändrad som koncept (cache-first, två nästa ej inställda avgångar). Den kan inte uppdateras automatiskt utan en separat verifierad bakgrundstjänst.

Åk hem söker till **en privat konfigurerad slutadress**, inte en tvingad slutstation. APR väljer bästa hållplats och inkluderar slutpromenaden. Tre bästa alternativ sorteras efter tidigast ankomst, därefter byten. Två syns samtidigt, svep för fler. Tryck på resa för delsträckor, svep för nästa steg. Start ger manuellt val av konfigurerade starthållplatser och fritextsökning via APR:s locations/by-text. Rubrik/Start-knapp uppdaterar.

## Position och uppdatering
- Garmin Position.getInfo() används för aktuellt eller senaste tidsstämplade fix (max 120 sekunder).
- Om otillräckligt: LOCATION_ONE_SHOT med 20 sekunders timeout. Då kan en max 5 minuter gammal känd position användas, tydligt markerad. Annars krävs ett manuellt val.
- Manuell starthållplats väljs uttryckligen; ingen falsk GPS-position och ingen tyst gissning baserad på IP-adress.
- Mobilens egen position är inte verifierad som tillgänglig i Connect IQ utan separat mobilkomponent. Garmin Connect används för HTTPS, inte som en garanterad positionskälla. Eventuell native mobilkomponent utvärderas senare.
- Full listvy uppdaterar vid öppning och ca var 60:e sekund så länge aktiv; detaljer fryses för läsning och visar dataålder. Manuellt uppdatera rubriken. Ingen kontinuerlig GPS, inga bakgrundssökningar. Stopp vid onHide. Widgetens timeout styrs av Garmin.
- Ingen position lagras i Git, på backend eller i en beständig klockcache; endast avgångar cachas i klockan. HTTPS, åtkomstnyckel, kort TTL för avgångar och rate limiting.

## API
GET /api/v1/departures?profile=home|work behåller v1-schemat och kompletterar med generatedEpoch och departureEpoch (unix sekunder).
GET /api/v1/journeys/home?lat=...&lon=... alternativt originKey=... returnerar generatedEpoch, destinationLabel och journeys (max 3). Varje resa har departureEpoch, arrivalEpoch, boardEpoch, line, boardStop, alightStop, changes, walkMeters (null om okänt), steps (kind, line, from, to, departureEpoch, arrivalEpoch, meters, index). Resans avgång avser när promenaden ska börja; påstigningstid är separat.
GET /api/v1/origins listar konfigurerade GID för manuellt val. GET /api/v1/origins/search?q=... söker hållplatsområden i APR; välj en träff, inte en gissad plats. Skydda alla med Authorization: Bearer privat åtkomstnyckel. Ingen loggning av query strings; även reverse proxy måste konfigureras så att position inte loggas.
GET /health är publik men innehåller inga känsliga värden.

## Installation
1. Node 22+. Kör cd backend och npm test. Inga externa npm-beroenden. Kopiera .env.example till en fil UTANFÖR repot. Sätt VASTTRAFIK_CLIENT_ID, VASTTRAFIK_CLIENT_SECRET, API-URL/token-URL från utvecklarportalen. Skapa en unik 32+ tecken lång WATCH_ACCESS_TOKEN. Sätt HOME_LAT och HOME_LON efter privat verifiering av slutadress (WGS84). Publicera inte adress, koordinater, tokens eller privat env-fil.
2. Verifiera alla stopAreaGid/riktningar via APR. Kopiera config/profiles.json till privat driftfil och peka PROFILES_FILE på den. Fail-closed om regler saknas. Testa särskilt rätt riktning och plattformsflytt. Ingen påhittad GID.
3. Starta lokalt: node --env-file=/private/venu.env src/server.mjs från backend/. Använd HTTPS reverse proxy med TLS, undvik accessloggar inklusive URL-query och skydda mot överlast. Bind normalt till loopback. Ingen extern drift har skapats. Verifiera /health och autentiserade API-anrop. Bekräfta verkliga fält och ev paginering/detaljer i APR; mockade enhetstester räcker inte.
4. Garmin SDK Manager, SDK med Venu 4 och VS Code Monkey C extension. Skapa lokal developer key. Öppna garmin/ och kör Monkey C: Build for Device på venu441mm och venu445mm; verifiera app-typ, resurser, behörighet, timer, JSON och alla callback-signaturer. Alternativt monkeyc -f monkey.jungle -d venu441mm -y /path/to/developer_key.der -o Transit.prg. Upprepa för 45 mm. Kör simulator och testa Glance A samt fullskärm, GPS-timeout, dålig GPS, offline, 429, startval, route details, swipe och uppdatering. Ingen signerad PRG skapad här.
5. Installera PRG privat på klockan enligt Garmin sideload. Konfigurera server-URL och åtkomstnyckel via Connect IQ appinställningar. Verifiera Bluetooth, verklig trafik och energiförbrukning. Gör manuell testresa till hemadress från minst tre olika platser, inklusive inomhus.

## Återstående kvalitetssäkring
- SDK saknas i utvecklingsmiljön; Monkey C är inte kompilerad.
- APR-credentials, verifierade stopp-ID/riktningar och hemkoordinater saknas; skarpa anrop ej körda.
- Upstream schema är baserat på dokumentation, inte faktiska svar. Verifiera stop details serviceJourneyCalls, tidsfält, paginering och access links. Vid schemafel får klienten felstatus, aldrig syntetisk data.
- Backendtest finns i CI. Kontrollera utfallet innan merge. Testa små/stora skärmar och om appinställningar kan användas vid sideload.
- Ingen separat telefonapp, ingen vibrerande avstigningsvarning i denna version, ingen automatisk publicering.
